# 時間外勤務申請 現行仕様確認版

Version: v0.2.1  
Status: 仕様摺り合わせ中 / develop

## 1. 基本方針
- 既存の時間外勤務申請書をWeb申請化する。
- 職員情報はログイン中の職員マスタから自動表示する。
- 申請、承認、差戻し、再申請、却下、最終承認、完了まで履歴を保持する。
- 正式提出後の申請は物理削除しない。

## 2. 届出年月日
- 職員による入力項目にはしない。
- 「申請する」を実行して正式提出した日をシステムが自動記録する。
- 下書き作成日は届出年月日としない。
- 差戻し後の再申請でも当初の届出年月日は維持し、再申請日時を履歴として記録する。

## 3. 申請者情報
自動表示: 職員番号 / 所属 / 氏名

## 4. 所定勤務時間・シフト
- 管理画面で部門ごとに基本勤務時間・シフトを登録する。
- 申請者は勤務日を指定し、その日のシフトを選択する。
- 選択候補は勤務日時点の申請者所属部門に登録された有効なシフトだけに絞り込む。
- 全部門のシフトを一括表示しない。
- シフト選択後、所定開始時刻・終了時刻・所定休憩時間を自動表示する。
- 選択したシフトIDと、その時点の名称・開始・終了・休憩時間を申請データに保存する。
- 後日シフトマスタが変更されても過去の申請内容は変わらない。

## 5. 時間外勤務入力
勤務日 / 当日のシフト / 所定勤務時間（自動） / 所定休憩（自動） / 時間外勤務開始・終了 / 時間外勤務時間（自動計算） / 必要な理由 / 時間外削減の取組み / 時間外勤務中の休憩 / 深夜勤務予定

## 6. 申請操作
下書き保存 / 申請 / 差戻し後の修正・再申請 / 規定上許可する場合の取下げ

## 7. 承認
- 申請書と承認経路は別管理。
- 申請者・所属等の条件から適用する承認経路を自動決定する。
- 固定承認者と「申請者の所属長」等の動的承認者を混在できる。
- 初期版は1ステップ1承認者、順次承認。
- 申請時に実際の承認者を確定して経路を固定する。
- 承認 / 差戻し / 却下。
- 差戻し・却下はコメント必須。
- 差戻し後は同じ申請番号で修正・再申請し、改訂履歴を保持する。

## 8. 最終承認後
- 正式な申請データを確定し、正式PDFを生成・保存する。
- 最終承認日時を記録する。
- 時間外勤務申請では勤怠・給与等の後処理タスクを作成する。
- 「最終承認済」と「勤怠処理完了」は別状態として管理する。

## 9. 通知
職員番号に紐づくメールアドレスを使用し、申請・承認依頼・差戻し・却下・再申請・最終承認・完了等を通知する。

## 10. GitHub / 環境運用
- develop: 開発・仕様確認中の最新版。
- main: テスト確認後に確定した本番リリース候補のソース。
- テスト環境: developを基準に実際に操作確認するサイト。
- 本番環境: mainで確定した版を職員が実運用するサイト。
- main自体が本番環境ではなく、GitHub上の確定ソースである。
- 当面は develop / main の2ブランチ運用とし、不要にブランチを増やさない。
